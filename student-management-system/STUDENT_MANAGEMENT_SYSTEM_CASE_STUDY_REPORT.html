PART A. Comprehensive Question

Case Study: Student Management System

An academic institution maintains student academic records in paper ledgers and disconnected spreadsheets. The department administration faces severe bottlenecks in tracking enrolled students across departments, updating semester/year progression, verifying unique roll numbers, and generating branch-wise enrolment summaries. The department chairperson requires a secure, web-based Student Management System that stores student records in a persistent cloud database, provides instant search, and is accessible anywhere via public cloud URLs.

Design and develop a database-driven Student Management System using React.js + Vite, Node.js, Express.js, and MongoDB Atlas. Deploy the frontend on Vercel and the backend on Render, making the full-stack system accessible over the internet via secure HTTPS.

The application must support the following requirements:

  • Store student profiles including Roll Number, Student Name, Email Address, Department, and Academic Year.
  • Create and manage a MongoDB database (studentdb) and collection (students) using an appropriate document structure.
  • Perform CRUD operations: register a student, display active student records, modify student branch/year details, and delete a student record with confirmation.
  • Write MongoDB queries to insert, retrieve, update, and delete documents.
  • Use aggregation to generate department-wise student counts and enrolment distribution.
  • Create an index on rollNumber (unique) to enforce data integrity and on department to support fast indexed filtering.
  • Deploy the backend (Render), frontend (Vercel), and database (MongoDB Atlas). Explain the role of cloud hosting, public domains, and environment variables.
  • Address Question 6 Diagnostic Requirements: Analyze and systematically resolve: (1) Incorrect API URL, (2) Environment Variables, (3) CORS Policy Violations, and (4) MongoDB Connectivity.
  • Test the deployed application and confirm that data entered through the live Vercel interface is stored in MongoDB Atlas and can be retrieved.

1. Analyse the requirements

Requirement Solution
Student Identity A unique university registration number (rollNumber) identifies each student document.
Student Details name, email, department, and year are stored in each BSON document.
Data Storage MongoDB Atlas cloud database: studentdb; collection: students.

Deployment MongoDB Atlas hosts cloud database; Render hosts Node.js/Express API; Vercel hosts React frontend.

2. Design the MongoDB document

A student record is represented as one BSON document in the students collection. A real document from our cluster is:

{ "_id": "6af30d29e28b0c9469c12440", "name": "Hari Charan", "rollNumber": "A24126552080", "email": "haricharan@amity.edu", "department": "CSE", "year": "3", "createdAt": "2026-11-10T12:25:13.498Z", "updatedAt": "2026-11-10T12:25:13.498Z" }

Field design:

Field Suggested Data Type Purpose Constraints
rollNumber String Unique university registration number Required, unique, trimmed
name String Full student display name Required, trimmed
email String Official academic email Required, unique, lowercase
department String Academic department (e.g. CSE, ECE) Required, Enum: CSE, ECE, EEE, MECH, CIVIL, IT
year String Academic study year Required, Enum: 1, 2, 3, 4

The MongoDB document also receives an automatically generated _id field (ObjectId). The application uses this identifier when editing or deleting a student.

5. Create indexes

An index can help MongoDB locate documents without scanning every document in the collection. Create a unique index for the student roll number and a secondary index for department-based searches:

db.students.createIndex({ rollNumber: 1 }, { unique: true }) db.students.createIndex({ department: 1 }) // View indexes db.students.getIndexes()

The unique rollNumber index guarantees that no two students can share the same roll number. The department index supports high-speed filtering queries.

6. Use aggregation for department-wise student summary

The department administrator wants to know the total count and list of students enrolled in each academic department:

db.students.aggregate([ { $group: { _id: "$department", studentCount: { $sum: 1 }, enrolledStudents: { $push: { name: "$name", rollNumber: "$rollNumber", year: "$year" } } } }, { $sort: { studentCount: -1 } } ])

Create client/src/App.jsx:

import { useState, useEffect } from 'react'; import Navbar from './components/Navbar'; import StudentForm from './components/StudentForm'; import StudentList from './components/StudentList'; import { getAllStudents, createStudent, updateStudent, deleteStudent } from './services/api'; import './App.css'; export default function App() { const [students, setStudents] = useState([]); const [editingStudent, setEditingStudent] = useState(null); const [searchTerm, setSearchTerm] = useState(''); const [message, setMessage] = useState(null); const fetchStudents = async () => { try { const res = await getAllStudents(); setStudents(res.data); } catch (err) { setMessage({ text: 'Failed to retrieve records from backend', type: 'error' }); } }; useEffect(() => { fetchStudents(); }, []); const handleAdd = async (data) => { const res = await createStudent(data); setStudents([res.data, ...students]); setMessage({ text: `Student ${res.data.name} registered!`, type: 'success' }); }; const handleUpdate = async (data) => { const res = await updateStudent(editingStudent._id, data); setStudents(students.map(s => s._id === editingStudent._id ? res.data : s)); setEditingStudent(null); }; const handleDelete = async (id) => { if (window.confirm('Delete this student record?')) { await deleteStudent(id); setStudents(students.filter(s => s._id !== id)); } }; return ( <div> <Navbar /> <div className="container"> {message && <div className={`message ${message.type}`}>{message.text}</div>} <StudentForm onSubmit={editingStudent ? handleUpdate : handleAdd} editingStudent={editingStudent} /> <StudentList students={students} searchTerm={searchTerm} onSearchChange={setSearchTerm} onEdit={setEditingStudent} onDelete={handleDelete} /> </div> </div> ); }

10. Deploy the application using cloud platforms

Deployment architecture:

Layer Platform Responsibility
Frontend Vercel Hosts the built React application and provides public HTTPS frontend URL.
Backend Render Runs the Node.js/Express API container and provides public API URL.
Database MongoDB Atlas Hosts the cloud MongoDB database and stores student documents permanently.

Deployment steps:

  1. Create a MongoDB Atlas cluster: Create a database user, configure Network Access to 0.0.0.0/0 ("Allow Access from Anywhere"), and copy the connection string.
  2. Push source folders to Git: Push the backend and frontend source folders to GitHub. Do not commit .env files or database credentials.
  3. Deploy backend on Render: Create a Web Service from the repository. Set Root Directory to student-management-system/server. Build command: npm install; Start command: npm start.
  4. Configure Render environment variables: Add MONGODB_URI and PORT=5000.
  5. Deploy frontend on Vercel: Import the repository into Vercel. Set Root Directory to student-management-system/client. Set VITE_API_URL to the public Render backend URL (https://student-api-a24126552080.onrender.com/api/students).
  6. Test live end-to-end communication: Test Create, Read, Update, Delete, and Search operations on the public Vercel URL.

Variable Where to set it Actual Deployed Value
